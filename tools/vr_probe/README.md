# Mario Kart 64 Steam Frame native OpenXR probe

This standalone ARM64 Linux executable tests the SteamVR/OpenXR Vulkan contract with two independent `PRIMARY_STEREO` eyes. It uses `XR_KHR_vulkan_enable2`, a runtime-created Vulkan instance and device, runtime-selected physical device, `XR_REFERENCE_SPACE_TYPE_LOCAL`, predicted display time, sRGB swapchain images with mutable UNORM image views, and per-eye acquire/wait/clear/submit/release handling. Each clear uses a Vulkan framebuffer backed by the UNORM view and returns the swapchain image to `VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL`. Left and right use distinct red- and blue-dominant clears. It exits nonzero if it cannot submit a valid stereo frame before the finite duration expires, then requests orderly session exit.

Build output is ignored under `build-linux-aarch64/vr_probe/`. Run as `../../build-linux-aarch64/vr_probe/mk64-frame-probe --seconds 30` from `tools/vr_probe` (the default duration is 30 seconds). A passing run prints runtime, system, GPU, eye sizes, session-state transitions, and the number of submitted stereo frames.

For a one-shot rendered-image diagnostic, use `../../build-linux-aarch64/vr_probe/mk64-frame-probe --seconds 30 --readback-dir /tmp/mk64-eye-readback`. The probe then requests transfer-source usage on its eye swapchains, copies the exact acquired images through host-visible staging after the UNORM framebuffer clear, returns each image to `COLOR_ATTACHMENT_OPTIMAL`, and releases those same images for submission. After the first successfully submitted stereo frame it writes `left.rgba`, `right.rgba`, `left.ppm`, and `right.ppm`, verifies every RGBA pixel against the expected distinct clear colors, requests orderly session exit, and finishes. If no valid rendered frame arrives before the duration expires, or the readback colors differ, the process fails. Ordinary runs without `--readback-dir` do not allocate staging buffers or perform image copies.

Build inside the `mariokart64recomp-frame:latest` ARM64 container with `./build.sh` (image SHA-256 `6cd15fa7941a706358920701a1ccb504852e8ebf1df6ebb0f4b92de6814455f4`). The script links `/opt/openxr/lib/libopenxr_loader.a` statically and the image's system Vulkan library dynamically. The resulting binary targets Ubuntu 22.04 / glibc 2.35 and contains no copied GPU driver.

The no-runtime check used `XR_RUNTIME_JSON=/tmp/no-openxr-runtime.json ../../build-linux-aarch64/vr_probe/mk64-frame-probe --seconds 1`; the loader could not find a runtime, the probe exited 1, and it reported zero submitted frames.
